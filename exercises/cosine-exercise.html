Before you play · Interactive introduction

How can numbers represent meaning?

Imagine a search engine that understands that “refund policy” and “returning a purchase” are related—even though the words are different. Embeddings make this possible by representing text as vectors: lists of numbers. Similar meanings often produce similar vectors.

We will use just two dimensions so you can see the geometry. Real embedding models commonly use hundreds or thousands of dimensions, and their coordinates are learned—not manually assigned meanings.

1. Semantic distance: How far apart?

Each dot is a vector's endpoint. In this illustrative map, related concepts sit near one another.

Distance compares positions. Close together often means more semantically similar, depending on the model and distance metric.

2. A vector: What do the numbers mean?

A 2D vector such as [3, 2] means 3 units along the horizontal axis and 2 units along the vertical axis. Draw an arrow from the origin to that point.

Each number is a component of the vector. A real embedding might look like [0.12, −0.43, 0.78, …] with many more components. Individual components do not usually have simple meanings.

3. Direction: Which way does it point?

Vectors have both direction and length. Two arrows can point in almost the same direction even if one is longer.

Changing length alone does not change cosine similarity. Changing direction does.

4. Cosine similarity: What is the angle?

Cosine similarity compares direction using the angle θ between two vectors. The smaller the angle (from 0° to 180°), the higher the cosine similarity.

cos(0°) = +1 (same direction) · cos(90°) = 0 (perpendicular) · cos(180°) = −1 (opposite). For 30°, cosine similarity ≈ 0.87.

When would we use each?

Euclidean distance — proximity

Use when: closeness of the actual vector positions matters, including magnitude.

Example: Grouping customer records by nearby numerical features, after appropriately scaling those features; or searching embeddings with a model designed for Euclidean distance.

Cosine similarity — alignment

Use when: you want to compare the direction of representations without letting vector length dominate.

Example: Semantic search that ranks document embeddings by how well their directions align with a question embedding, when the embedding model recommends cosine similarity.

Important: Neither measure is inherently more “semantic.” Choose the measure the embedding model was trained and evaluated to use. For unit-length (normalized) vectors, Euclidean distance and cosine similarity give the same ranking. Cosine similarity is undefined for a zero vector.

Which measure should we use?

Distance asks how far apart two points are. Cosine similarity asks how closely their arrows point in the same direction. Use Euclidean distance when absolute separation and magnitude matter (for example, spatial locations or feature spaces trained for Euclidean nearest-neighbor search). Use cosine similarity when relative direction matters more than magnitude (often semantic text retrieval). Neither is universally better: follow the embedding model’s recommended metric. For unit-normalized vectors, both give the same ranking.

In the game, you’ll compare vector directions first, test why length is not cosine similarity, and then use cosine similarity to retrieve relevant documents.
